# Worklog

[English](README.en.md)

Worklog อ่าน log ของ Claude Code และ Codex ที่อยู่ในเครื่องคุณ แล้วทำหน้าเว็บในเครื่องที่บอกว่างานแต่ละโปรเจคค้างอยู่ตรงไหน ทำด้วยบัญชีไหน และควรกลับไปทำอะไรต่อ เหมาะกับคนที่เปิดงานหลายโปรเจคพร้อมกัน ใช้หลายบัญชีสลับกันตอนติด limit หรือใช้ทั้ง Claude Code และ Codex

ทุกอย่างทำงานในเครื่อง ไม่มี server ภายนอก และไม่ต้องสมัครหรือ login อะไรเพิ่ม

## ทำอะไรได้บ้าง

- ทำอะไรต่อดี: จัดลำดับโปรเจคจากหลายอย่าง เช่น session จบเพราะติด limit หรือถูกหยุดกลางคัน มีกำหนดส่งใกล้ ทำล่าสุดเมื่อไหร่ และรออะไรอยู่ ทุกการ์ดบอกเหตุผลว่าทำไมได้ลำดับนั้น
- แนะนำบัญชี: ดูว่าบัญชีไหนติด limit ถึงเมื่อไหร่ แล้วบอกว่าควรทำต่อด้วยบัญชีไหน
- กลับไปทำต่อ: ถ้า session เปิดจากแอป จะบอกชื่อ session ที่ต้องหาในแถบด้านซ้าย ถ้าเปิดจาก terminal จะมีคำสั่ง resume ให้คัดลอก และทุกการ์ดมี prompt สำหรับเปิด session ใหม่พร้อมสรุปงานเดิม ใช้ตอนต้องเปลี่ยนบัญชี
- สรุปด้วย AI: สรุปแต่ละ session และแต่ละโปรเจคว่าทำอะไรเสร็จ อะไรค้าง ขั้นต่อไปคืออะไร และมีกำหนดส่งอะไรบ้าง
- จับงานทับซ้อน: เตือนเมื่อสอง session แก้ไฟล์เดียวกันในเวลาใกล้กัน หรือเปิดหลาย session ในโปรเจคเดียวกัน
- hook ของ Claude Code (ติดตั้งหรือไม่ก็ได้): เตือน Claude ก่อนแก้ไฟล์ที่อีก session เพิ่งแก้ และส่งสรุปงานล่าสุดของโปรเจคให้ session ใหม่อ่านก่อนเริ่ม

## สิ่งที่ต้องมี

- Node.js 24 ขึ้นไป (ใช้ `node:sqlite` ที่มากับ Node ไม่ต้องติดตั้ง package เพิ่ม)
- Claude Code หรือ Codex อย่างน้อยหนึ่งตัว ที่เคยใช้ในเครื่องนี้แล้ว
- ถ้าจะใช้สรุปด้วย AI ต้องมีคำสั่ง `claude` ที่ login ไว้แล้ว หรือ API key ของ Gemini, Groq หรือ OpenRouter หรือ Ollama ในเครื่อง

## ติดตั้ง

### Windows แบบไม่ใช้ terminal

1. ดาวน์โหลดไฟล์ `Worklog-Setup-<เวอร์ชัน>.exe` จากหน้า [Releases](https://github.com/Teerapab149/claude-worklog/releases) อันล่าสุด
2. ดับเบิลคลิกไฟล์ที่ได้ ถ้า Windows ขึ้นหน้าต่าง "Windows protected your PC" ให้กด More info แล้วกด Run anyway (ขึ้นเพราะไฟล์ยังไม่ได้เซ็นชื่อ)
3. เลือกว่าจะให้สร้างไอคอนบนหน้าจอ และติดตั้ง hook ใน Claude Code หรือไม่ แล้วกด Install

ตัวติดตั้งมี Node มาให้ในตัว ไม่ต้องติดตั้งอะไรเพิ่ม และไม่ต้องใช้สิทธิ์ admin ตอนติดตั้งจะอ่าน log เพื่อหาโฟลเดอร์โปรเจคและบัญชีให้เอง แก้ภายหลังได้ในหน้าตั้งค่า ค่าที่ตั้งไว้และข้อมูลของ Worklog เก็บอยู่ที่ `%LOCALAPPDATA%Worklog` ซึ่งจะยังอยู่เมื่ออัปเดตหรือถอนการติดตั้ง ถ้าไม่ต้องการแล้วลบโฟลเดอร์นี้ได้เลย ถอนการติดตั้งได้ที่ Settings ของ Windows ในส่วน Apps

### จาก source

```bash
git clone https://github.com/Teerapab149/claude-worklog.git
cd claude-worklog
npm run setup
npm run shortcut:install
```

`npm run setup` อ่าน log ในเครื่อง หาโฟลเดอร์ที่เก็บโปรเจคไว้และบัญชี Claude ที่เคยใช้ แล้วถามชื่อเรียกบัญชี ผลจะบันทึกไว้ที่ `config.local.json` ซึ่งไม่ถูก commit ลง git

`npm run shortcut:install` วางไอคอน Worklog ไว้บน Desktop และใน Start menu (ตอนนี้ทำได้เฉพาะ Windows) ดับเบิลคลิกแล้ว Worklog จะเปิดเป็นหน้าต่างของตัวเองผ่าน Edge หรือ Chrome ไม่มีแท็บและช่องที่อยู่เว็บ กดซ้ำตอนที่เปิดอยู่จะดึงหน้าต่างเดิมขึ้นมา พอปิดหน้าต่างประมาณ 10 วินาที ทุกอย่างก็ปิดตาม ไม่มีอะไรค้างในเครื่อง เอาไอคอนออกได้ด้วย `npm run shortcut:uninstall` ถ้าอยากให้แถบด้านบนของหน้าต่างเป็นสีเดียวกับหน้า ให้กด "ติดตั้งเป็นแอป" ในหน้าตั้งค่าหนึ่งครั้ง แล้วปิดหน้าต่างและเปิดใหม่จากไอคอนเดิม บนเครื่องอื่นใช้ `npm run app` เพื่อเปิดแบบเดียวกัน หรือใช้ `npm start` แล้วเปิด http://localhost:4317 ในเบราว์เซอร์

ถ้าอยากให้เซิร์ฟเวอร์เปิดค้างไว้ตลอด เช่น จะให้สรุปด้วย AI ทำงานเบื้องหลังตลอดเวลา

```bash
npm run autostart:install
```

บน Windows จะวางตัวเปิดไว้ในโฟลเดอร์ Startup บน macOS ใช้ launchd และบน Linux ใช้ systemd แบบผู้ใช้ เลิกได้ด้วย `npm run autostart:uninstall` ถ้าเซิร์ฟเวอร์เปิดอยู่แล้ว ไอคอนจะเปิดแค่หน้าต่าง และปิดหน้าต่างแล้วเซิร์ฟเวอร์ยังเปิดอยู่ต่อ

## hook ของ Claude Code

```bash
npm run install-hooks
```

คำสั่งนี้เพิ่ม hook สามตัวลงใน `~/.claude/settings.json` โดยสำรองไฟล์เดิมไว้ที่ `data/backups` ก่อน ใช้กับทุกบัญชีในเครื่องเดียวกัน และมีผลกับ session ที่เปิดหลังจากติดตั้ง

- `PreToolUse` ก่อน Claude แก้ไฟล์ ถ้ามี session อื่นแก้ไฟล์นั้นภายใน 30 นาที การแก้ครั้งแรกจะถูกกันไว้พร้อมบอกว่าใครแก้ไปเมื่อไหร่ Claude จะอ่านไฟล์ใหม่และบอกคุณ ถ้าแก้ซ้ำจะผ่าน
- `SessionStart` บอก session ใหม่ว่ามี session อื่นเปิดอยู่ในโปรเจคเดียวกันไหม และส่งสรุปงานล่าสุดของโปรเจคให้อ่าน
- `SessionEnd` บอกหน้าเว็บให้อ่าน log ของ session ที่เพิ่งจบทันที

คำสั่งเดียวกันนี้ตั้ง status line ของ Claude Code ให้ด้วย ถ้ายังไม่ได้ตั้งเอง status line จะได้ตัวเลขว่าใช้ limit 5 ชั่วโมงและรายสัปดาห์ไปกี่เปอร์เซ็นต์ (เฉพาะบัญชี Pro และ Max) Worklog เก็บตัวเลขนี้ไว้แสดงเป็นหลอดในหน้าบัญชี เพราะ log ของ Claude Code ไม่ได้บันทึกตัวเลขนี้ ส่วน Codex บันทึกไว้ใน log อยู่แล้ว ถ้าคุณตั้ง status line ของตัวเองไว้ก่อน Worklog จะไม่ทับ แต่จะไม่เห็นเปอร์เซ็นต์ของ Claude

status line ทำงานเฉพาะ Claude Code ที่เปิดใน terminal เท่านั้น แอป Claude desktop ไม่ได้เรียก ถ้าใช้แต่แอป desktop ให้ดูในหน้า Usage ของแอปว่าบัญชีไหนใช้ครบแล้ว จากนั้นเปิดหน้าบัญชีของ Worklog กด "บอกว่าบัญชีนี้ติด limit" เลือกช่วง (รายสัปดาห์หรือ 5 ชั่วโมง) และเวลาที่รีเซ็ต Worklog จะไม่แนะนำบัญชีนั้นจนถึงเวลานั้น หรือจนกว่าคุณจะกด "ใช้ได้แล้ว"

แต่ละ hook ใช้เวลาประมาณ 200 มิลลิวินาที ถ้า hook มีปัญหาจะเขียน error ไว้ที่ `data/hook.log` และไม่ขวางงาน เอาออกได้ด้วย `npm run uninstall-hooks`

## ความเป็นส่วนตัว

- หน้าเว็บรับเฉพาะการเชื่อมต่อจากเครื่องตัวเอง (`127.0.0.1`) และปฏิเสธ request ที่ส่งมาด้วยชื่อ host อื่น
- ข้อมูลที่อ่านได้เก็บใน `data/index.db` ในโฟลเดอร์นี้ ไม่ส่งไปที่ไหน
- ถ้าติดตั้งด้วยตัวติดตั้ง Worklog จะถาม GitHub ว่ามีเวอร์ชันใหม่ไหมทุกครั้งที่เปิด และทุก 6 ชั่วโมงระหว่างเปิดอยู่ คำถามนี้ไม่ได้ส่งข้อมูลของคุณไปด้วย ถ้ามีเวอร์ชันใหม่จะดาวน์โหลดไฟล์ติดตั้งจาก release ของ repo นี้ ตรวจว่าไฟล์ตรงกับ SHA-256 ที่ GitHub บอกไว้ แล้วติดตั้งเองหลังจากปิดหน้าต่าง ปิดได้ในหน้าตั้งค่า ส่วนที่รันจาก source จะไม่ถามและไม่อัปเดตเอง
- นอกจากนั้น สิ่งเดียวที่ออกจากเครื่องคือตอนสรุปด้วย AI ซึ่งส่งบทสนทนาบางส่วนไปที่ Claude ผ่านคำสั่ง `claude -p` ด้วยบัญชีของคุณเอง หรือถ้าเลือก "API แบบ OpenAI" ในหน้าตั้งค่า จะส่งไปที่ผู้ให้บริการที่เลือกแทน (Gemini, Groq, OpenRouter หรือที่อยู่ที่ใส่เอง) ถ้าเลือก Ollama ทุกอย่างอยู่ในเครื่อง API key เก็บใน `config.local.json` ในเครื่องนี้เท่านั้น และหน้าเว็บไม่เคยได้รับ key กลับไป บริการบางแห่งที่ใช้ฟรีอาจเอาข้อมูลที่ส่งไปใช้ปรับปรุงโมเดล ให้อ่านเงื่อนไขของผู้ให้บริการก่อน ก่อนส่งจะซ่อน key, token และรหัสผ่านที่ดูออก การสรุปใช้โควต้าของบัญชีนั้นด้วย ครั้งแรกที่เปิดจะสรุปทุก session ที่มีข้อความใหม่ใน 7 วันล่าสุด (ตั้งได้ที่ `summary.autoDays`) ใช้โมเดล Haiku ทีละ session ถ้าทุกบัญชีติด limit จะหยุดรอเอง ปิดได้ด้วย `"summary": { "enabled": false }`

## การใช้ทรัพยากรเครื่อง

ตอนเปิดแอป เซิร์ฟเวอร์ใช้หน่วยความจำประมาณ 70 MB และหน้าต่างแอปประมาณ 170 MB (ปิด GPU และส่วนเสริมของเบราว์เซอร์ที่ไม่ต้องใช้ไว้) ปิดหน้าต่างแล้วไม่ใช้อะไรเลย ระหว่างเปิด เซิร์ฟเวอร์อ่าน log ใหม่เฉพาะตอนมีไฟล์ log เปลี่ยน (ห่างกันอย่างน้อย 30 วินาที) และอ่านต่อจากจุดเดิม จึงใช้เวลาครั้งละประมาณ 0.1 วินาที

hook ของ Claude Code ทำงานได้แม้ปิดแอปอยู่ เพราะอ่านฐานข้อมูลเอง ส่วนสรุปด้วย AI ทำเฉพาะตอนแอปเปิดอยู่

## ตั้งค่า

แก้ค่าที่ใช้บ่อยได้ในหน้าตั้งค่าของ Worklog ได้แก่ โฟลเดอร์โปรเจค โฟลเดอร์ที่ไม่นับ ชื่อบัญชี การสรุปด้วย AI (Claude Code CLI ซึ่งหน้าตั้งค่าจะบอกว่า login ด้วยบัญชีไหน หรือ API แบบ OpenAI พร้อมปุ่มทดสอบ key) และการเตือนงานทับซ้อน กดบันทึกแล้วมีผลทันที ยกเว้นการเปิดสรุปด้วย AI ที่เคยปิดไว้ ซึ่งจะเริ่มเมื่อเปิด Worklog ใหม่ ถ้าเปลี่ยนโฟลเดอร์โปรเจค Worklog จะจัดกลุ่มใหม่เองโดยไม่ต้องอ่าน log ใหม่ทั้งหมด

ค่าทั้งหมดเก็บอยู่ใน `config.local.json` ค่าที่ไม่มีในหน้าตั้งค่าแก้ในไฟล์นี้ได้ ดูตัวอย่างได้ที่ [config.example.json](config.example.json)

| ค่า | ความหมาย |
|---|---|
| `roots` | โฟลเดอร์ที่เก็บโปรเจคไว้ข้างใน แต่ละโฟลเดอร์ย่อยนับเป็นหนึ่งโปรเจค session ที่อยู่นอก root จะจัดกลุ่มตามโฟลเดอร์ของตัวเอง |
| `exclude` | โฟลเดอร์ที่ไม่ต้องนับ เช่น โฟลเดอร์ทดสอบ |
| `projectNames` | ชื่อที่แสดงของแต่ละโปรเจค ใช้ชื่อโฟลเดอร์เป็น key |
| `accounts` | ชื่อเรียกบัญชี ใช้รหัสบัญชีเป็น key |
| `overlap.windowMinutes` | สองการแก้ไฟล์ห่างกันไม่เกินกี่นาทีถึงนับว่าทับกัน ค่าเริ่มต้น 30 |
| `overlap.preToolUse` | hook ทำอะไรเมื่อเจองานทับ `deny_once` กันครั้งแรก, `ask` ให้คุณตัดสิน, `context` แค่แจ้ง Claude, `off` ไม่ทำอะไร |
| `summary.enabled` | เปิดหรือปิดการสรุปด้วย AI |
| `summary.model` | โมเดลที่ใช้สรุป ค่าเริ่มต้น `haiku` |
| `summary.autoDays` | สรุปเองเฉพาะ session ที่มีข้อความใหม่ภายในกี่วัน ที่เก่ากว่านั้นสรุปเมื่อกดในหน้าเว็บ |
| `claudeDir`, `codexDir` | ตำแหน่งข้อมูลของแต่ละเครื่องมือ ถ้าไม่ตั้งจะใช้ `~/.claude` และ `~/.codex` |
| `port` | port ของหน้าเว็บ ค่าเริ่มต้น 4317 |
| `app.browser` | ตำแหน่งไฟล์โปรแกรมเบราว์เซอร์ที่ใช้เปิดหน้าต่างแอป ถ้าไม่ตั้งจะหา Edge ก่อน แล้วค่อยหา Chrome |

ถ้าแก้ `roots` ในไฟล์เองหลังจากใช้ไปแล้ว ให้รัน `npm run scan -- --full` เพื่อจัดกลุ่มโปรเจคใหม่ (สรุปด้วย AI ที่มีอยู่จะต้องสรุปใหม่) ถ้าแก้ในหน้าตั้งค่า Worklog จะจัดกลุ่มให้เองโดยไม่ลบสรุปที่มีอยู่

## ข้อจำกัด

- รูปแบบ log ของ Claude Code และ Codex ไม่ใช่ API ที่มีเอกสาร ถ้าเครื่องมือเปลี่ยนรูปแบบ ตัวอ่านอาจต้องแก้ ตัวอ่านเขียนให้ข้ามบรรทัดที่อ่านไม่ออกโดยไม่พัง
- hook มีเฉพาะ Claude Code ส่วน Codex ยังไม่มี
- ตัวเปิดเองตอน login บน macOS และ Linux ยังไม่ได้ทดสอบบนเครื่องจริง ถ้าเจอปัญหาแจ้งใน issue ได้
- ยังไม่อ่าน Cursor, Antigravity และเครื่องมืออื่น

ตัวอ่าน log ของแต่ละเครื่องมืออยู่ใน `src/sources/` ถ้าจะเพิ่มเครื่องมือใหม่ ให้ทำตัวอ่านที่ส่งข้อมูลรูปแบบเดียวกับตัวที่มีอยู่

ตัวติดตั้งสร้างด้วย `node tools/build-installer.js` ซึ่งต้องมี [Inno Setup 6](https://jrsoftware.org/isinfo.php) ในเครื่อง ถ้าไม่มีจะเตรียมไฟล์ไว้ใน `dist/stage` แล้วหยุด เวลาออกเวอร์ชันใหม่ ให้แก้ `version` ใน `package.json` แล้ว push tag ชื่อเดียวกัน เช่น `v0.2.0` GitHub Actions จะสร้าง `Worklog-Setup-0.2.0.exe` แล้วแนบไว้ใน release ให้เอง
